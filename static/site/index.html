Features

不只是能跑,是算得准

从棋盘表示到搜索剪枝,每一层都为速度与强度让路。

Expectimax 双递归

2048 是"玩家 + 随机出块"的不完全信息博弈:玩家走位确定,取 max;出块随机,取期望。用 expectimax 而非 minimax,才对得上这个游戏的本质。

move_node(b) = max over 4 方向的 tilechoose(移动后) tilechoose(b, p) = Σ 每空格 × {2: 0.9, 4: 0.1} × move_node(放块后)

64 位 bitboard

整个 4×4 棋盘压进一个整数,每格 4 bit 存 rank。一次移动就是一趟位运算,棋盘状态可直接当哈希键。

65536 项查找表

移动与评分全部预计算成 6 张表,运行时只查表。Python 也能跑到约 47 万节点/秒。

概率截断 + 递进深度

累计概率低于阈值的分支直接截止;深度随局面中不同数字的种数增减——开局浅、残局深,算力花在刀刃上。

助手模式:AI 出推荐,你走棋

为真实对局设计。输入当前棋盘 → 看最优着法与四方向期望分 → 在真实游戏中走出同样方向 → 录个新出的方块 → 继续。左键点格子数值乘 2,右键清空,键盘也能直接改。

① 输入棋盘 → ② AI 推荐 → ③ 走棋 → ④ 录新块

4 套主题 + 真实滑动

方块按身份追踪做 transform 滑动,合并脉冲、新块弹入。全程尊重系统减少动效偏好。

Algorithm

搜索树里发生的每一毫秒

三层结构:棋盘表示 → 启发式评分 → 带剪枝的 expectimax 搜索。

01启发式评分

每行按四项打分,行列各算一次求和:

heur = 200000                  # 失败重罚
      + 270  × 空格数
      + 700  × 可合并对数
      − 47   × min(左单调性, 右单调性)
      − 11   × Σ rank^3.5

分别对应四个 2048 核心策略:保空格、造可合并、维持单调、压制总数。注意:这个分值在百万量级,只用于方向之间比大小,不是游戏分数。

02两个关键剪枝

概率截断 — 出块位置的概率乘积衰减极快,累计概率低于 0.0001 的分支直接按启发分截止,搜索树砍掉一大截而强度几乎无损。

递进深度 — max(3, 盘面不同数字种数 − 2)。开局分支爆炸搜得浅,残局分支收缩值得深挖。

03纯 Python 的两个工程处理

有界循环 — 编译型语言靠定宽整数溢出归零来结束位移循环,Python 大整数无上限会死循环,必须显式限制次数。

迭代加深 + 死线 — 从深度 1 逐层加深,超时回退到最近完成的深度,保证任何机器都在预算内出推荐。
